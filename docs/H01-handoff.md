# H01 — регистрация перед первым AI-ответом

## Цель и вариант

Гипотеза H01: preview AI-ответа на рабочий вопрос с регистрацией для полного ответа повысит долю новых аккаунтов среди уникальных посетителей главной страницы. В прототипе вариант показывается всем посетителям; реальный эксперимент здесь не запускается.

Путь пользователя: гость вводит вопрос → показываются краткий ответ и закрытая часть → регистрация по CTA → после demo email-кода пользователь возвращается к тому же AI-блоку → уже сформированный полный ответ раскрывается без повторного запроса. После входа доступны уточнения в сохранённой истории.

## Реализовано

- На главной первый запрос гостя формирует безопасный preview AI-ответа, но объяснение, материалы и шаги скрыты регистрационным блоком.
- Кнопки «Войти» и «Регистрация» в шапке открывают разные формы.
- Demo email → код явно подписан: письмо не отправляется, аккаунт не создаётся, пароль не запрашивается. Demo-регистрация и вход записываются только в локальный console event, а не в Метрику.
- После успешной формы полный уже сформированный ответ раскрывается в том же чате. Повторный callback, двойной клик и retry используют `idempotencyKey`; route handler возвращает закешированный результат без повторного вызова AI.
- История и demo-вход существуют только в памяти текущей страницы и очищаются после обновления. «Очистить историю» очищает историю сразу. Для реального AI-провайдера в каждый запрос передаётся весь диалог текущей страницы; в demo mode ответ по-прежнему строится из локального поиска.
- На главной нет числового лимита ответов. На первом ответе нет подписочного paywall: вместо него показывается регистрация для раскрытия ответа.
- Есть загрузка, состояние ошибки с тем же ключом повторной попытки и ответ при отсутствии материалов.
- Дисклеймер выводится перед отправкой и рядом с каждым ответом.
- Демонстрационные материалы обозначены как непроверенные и не ведут на `?demo-material=…` как на реальный источник.
- В `lib/auth.ts` создан серверный адаптер. При `AUTH_MODE=real` `/api/auth/session` и `/api/chat` проверяют сессию на сервере. В реальном сайте нужно заменить TODO на проверку подписанной сессии или вызов действующего провайдера.

## Интеграции и данные

- `AI_API_KEY`, `AI_BASE_URL` и `AI_MODEL` читаются только на сервере в `lib/ai.ts`.
- Настоящая email-доставка, создание пользователя, пароли, OAuth и социальные сети не реализованы.
- Для production следует подключить auth provider в `lib/auth.ts` и заменить in-memory idempotency cache на общее хранилище (Redis/БД) с TTL.
- In-memory cache защищает этот прототип в рамках одного процесса. После рестарта сервера повторный запрос не должен считаться надёжно идемпотентным без production-хранилища.

## События

В Метрику без текста вопроса, email и кода: `h01_variant_view`, `h01_question_submit`, `h01_registration_offer`, `h01_registration_start`, `h01_existing_login`, `h01_chat_return`, `h01_answer_view`, `h01_answer_error`.

`h01_demo_registration_*` и `h01_demo_existing_login_*` — только локальные console events. Они не вызывают `ym`.

## План A/B для пилота

Перед пилотом распределять уникальных посетителей 50/50 по стабильному варианту: control получает текущий путь, H01 — регистрацию перед первым ответом. Основная метрика: `новые аккаунты за тот же визит / уникальные участники варианта`. Вход существующего пользователя не является регистрацией.

Дополнительно собирать: отправку сообщения, предложение/начало/успех регистрации, возврат в чат, показ ответа, ошибки и время от отправки до ответа. Не передавать в аналитику текст вопроса, email, коды или содержимое ответа. Первые 24 часа — только начальный технический пилот для проверки воронки и качества событий; они не гарантируют статистическую значимость.

## Критерии приёмки

1. Гость видит только краткий ответ, а объяснение, материалы и шаги раскрываются после demo регистрации.
2. Вопрос и preview переживают закрытие формы и перезагрузку страницы.
3. После кода раскрывается тот же ответ без повторного запроса, а retry не уменьшает остаток второй раз.
4. В шапке «Войти» и «Регистрация» ведут к разным формам; пароль нигде не запрашивается.
5. Историю можно очистить, уточнение доступно после первого ответа, а страницы статьи и персонального ответа продолжают работать.
6. На мобильной ширине форма складывается в одну колонку; поля и кнопки доступны Tab, Enter и Escape.
7. `npm run lint` и `npm run build` проходят.
